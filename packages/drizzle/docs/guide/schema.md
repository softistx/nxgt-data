# Columns and schema

The columns nearly every table has — a primary key, `createdAt`/`updatedAt`,
`deletedAt`, and on a table several people edit, `version` and
`createdBy`/`updatedBy`/`deletedBy` — as helpers, declared so that
[the repository](repository.md) recognises them.

```ts
import { pgTable, text } from 'drizzle-orm/pg-core';
import { id, softDelete, timestamps } from '@nxgt/drizzle/pg';

export const users = pgTable('users', {
	id: id(),
	email: text('email').notNull().unique(),
	name: text('name'),
	...timestamps(),
	...softDelete(),
});
```

`users.$inferSelect` is now
`{ id: string; email: string; name: string | null; createdAt: Date; updatedAt: Date; deletedAt: Date | null }`.

## What each helper gives

| Helper | Column(s) | SQL |
| --- | --- | --- |
| `id()` | `id` | `uuid primary key default gen_random_uuid()` |
| `id('uuid')` | `id` | the same, written out |
| `id('identity')` | `id` | `integer primary key generated by default as identity` |
| `timestamps()` | `createdAt`, `updatedAt` | `created_at` / `updated_at timestamptz(3) not null default now()`, `updatedAt` with `$onUpdate` |
| `softDelete()` | `deletedAt` | `deleted_at timestamptz(3)`, nullable |
| `version()` | `version` | `integer not null default 0`: the [optimistic lock](stamps.md#optimistic-locking) |
| `actors()` | `createdBy`, `updatedBy`, `deletedBy` | `created_by` / `updated_by` / `deleted_by uuid`, nullable, no foreign key: [who is writing](stamps.md#who-is-writing) |
| `actors('text')`, `actors('integer')` | the same | the same, as `text` or `integer` |

They are ordinary Drizzle builders, so keep chaining:

```ts
import { integer, pgTable, text } from 'drizzle-orm/pg-core';
import { id } from '@nxgt/drizzle/pg';

export const teams = pgTable('teams', {
	id: id('identity'), // 1, 2, 3… instead of a uuid
	name: text('name').notNull().unique('teams_name_unique'),
	seats: integer('seats').default(5),
});
```

**Call them once per table.** Each call returns new builders; a builder shared
between two tables belongs to the first one.

## Why `timestamptz(3)`

PostgreSQL stores a `timestamptz` to the microsecond, and a JavaScript `Date`
only to the millisecond. Read back into a `Date`, a stored value is no longer
the value the database holds — and a cursor built on it repeats or skips rows.
`timestamps()` and `softDelete()` therefore declare `precision: 3`. A
timestamp column of your own that a cursor will page along wants the same:

```ts
import { pgTable, text, timestamp } from 'drizzle-orm/pg-core';
import { id } from '@nxgt/drizzle/pg';

export const posts = pgTable('posts', {
	id: id(),
	title: text('title').notNull(),
	publishedAt: timestamp('published_at', { withTimezone: true, precision: 3 }),
});
```

See [guide/pagination.md](pagination.md#cursor-pages) for the cursor rules.

`timestamps()` has two clocks: `createdAt` and the default of `updatedAt` are
the database's `now()`, while `$onUpdate` is `new Date()` in your process.

## What the repository reads from the table

`createRepository` looks the table up once, by key on the table object:

| Key | Effect |
| --- | --- |
| `id` | the column the methods by id use, unless `primaryKey` names another |
| `deletedAt` | soft delete is on: `delete` sets it, reads leave those rows out |
| `updatedAt` | set to `now()` on every update, unless the column has `$onUpdate` |
| `version` | an integer `NOT NULL` one is the optimistic lock: raised on every update, checked by `update` |
| `createdBy`, `updatedBy`, `deletedBy` | stamped from the actor of `as(actor)` or the `actor` option |

So the names above are the ones that matter — `deletedAt`, not
`deleted_at`, which is only the column's name in SQL. A table declared with
plain Drizzle columns under those keys behaves exactly like one declared with
the helpers.

## Migrations

This package writes no DDL and ships no CLI: the tables are yours, and
`drizzle-kit` (or your own SQL) creates them. What `id()`, `timestamps()` and
`softDelete()` produce is the SQL in the table above.

One thing to write by hand: a unique constraint on a soft-deleted table
should ignore the deleted rows, or a deleted `ada@example.com` keeps the
address forever.

```sql
create unique index users_email_live on users (email) where deleted_at is null;
```

## Signatures

```ts
function id(): SetHasDefault<SetIsPrimaryKey<PgUUIDBuilder>>;
function id(kind: 'uuid'): SetHasDefault<SetIsPrimaryKey<PgUUIDBuilder>>;
function id(kind: 'identity'): HasIdentity<SetIsPrimaryKey<PgIntegerBuilder>, 'byDefault'>;

function timestamps(): {
	createdAt: SetHasDefault<SetNotNull<PgTimestampBuilder>>;
	updatedAt: SetHasDefault<SetHasDefault<SetNotNull<PgTimestampBuilder>>>;
};

function softDelete(): { deletedAt: PgTimestampBuilder };

function version(): { version: SetHasDefault<SetNotNull<PgIntegerBuilder>> };

function actors(): { createdBy: PgUUIDBuilder; updatedBy: PgUUIDBuilder; deletedBy: PgUUIDBuilder };
function actors(kind: 'uuid'): { createdBy: PgUUIDBuilder; updatedBy: PgUUIDBuilder; deletedBy: PgUUIDBuilder };
function actors(kind: 'text'): { createdBy: PgTextBuilder; updatedBy: PgTextBuilder; deletedBy: PgTextBuilder };
function actors(kind: 'integer'): { createdBy: PgIntegerBuilder; updatedBy: PgIntegerBuilder; deletedBy: PgIntegerBuilder };
```
