# @nxgt/redis-guard

## 0.2.0

### Minor Changes

- [#116](https://github.com/softistx/nxgt-data/pull/116) [`8848879`](https://github.com/softistx/nxgt-data/commit/88488793cdbb1cfc48cdd2fd9e1230dfbfe57efa) Thanks [@SteveGT96](https://github.com/SteveGT96)! - Idempotency: `defineIdempotency({ name, key, ttl, lease, schema })` describes an operation and `bindIdempotency(client, definition)` binds it, with `run(params, work, { fingerprint })` and `forget(params)`. The first call with a key runs `work`, checks its result against the zod schema, and keeps it for `ttl` **seconds**; a repeat gets `{ value, replayed: true }` without calling `work`. A repeat while the first still runs rejects with `IN_PROGRESS` and a `retryAfter` in milliseconds; a different fingerprint — a SHA-256 of the string or bytes you pass, the raw body usually — rejects with `MISMATCH`; a result the schema refuses, or a stored one it no longer reads, rejects with `INVALID`, and a stored one is **not** treated as a miss. An error thrown by `work` is never stored: the key is released and the error passes through as the same object. A failure that must replay is returned as a union member of the schema. The running call holds a lease of `lease` **milliseconds** (default 10 000), which this version does not renew: work that outlasts it can run twice, and the late run rejects with `LEASE_LOST` and stores nothing. Each step is one Lua script over one hash, timed by the Redis server.
  
  **Breaking for installs: `zod` is now a required peer**, `>=4.6.5 <5`. Every consumer must install it — `bun add zod` — even one that only uses rate limits, which parse nothing.

## 0.1.0

### Minor Changes

- [#113](https://github.com/softistx/nxgt-data/pull/113) [`224af7d`](https://github.com/softistx/nxgt-data/commit/224af7d7da901d5995238e0809bc14659db25856) Thanks [@SteveGT96](https://github.com/SteveGT96)! - First release of `@nxgt/redis-guard`, guards on Bun's own `RedisClient`, starting with rate limits. `defineRateLimit({ name, key, limit, per, burst })` describes a limit and `bindRateLimit(client, definition)` binds it, with `consume`, `enforce`, `peek` and `reset`, and an optional `cost` per call. Each check is GCRA as one Lua script over one key, holding the latest server time the bucket has seen and the bucket's offset beyond it, sent by its SHA-1 and falling back to `EVAL` on `NOSCRIPT`. The script is timed by the Redis server's `TIME`, never the host's clock, and a server clock that goes back never refills a bucket, as long as it is at most one full refill behind. A stored string the script could not have written reads as a full bucket; a key of another type fails with Redis's own `WRONGTYPE`. A denial and a `peek` write nothing, and the key expires when its bucket is full again. The script counts in exact integers, in units of 1/limit µs, so a burst taken one request at a time allows exactly the burst at any rate; a `burst × per` above what that can hold exactly (9,007,199,254,740) is refused at definition. Every result is a delay in milliseconds (`resetAfter`, `retryAfter`), never a date. Its error is `GuardError`, with `RATE_LIMITED` (carrying `retryAfter`) and `COST`, naming the definition and never the key or the params.
