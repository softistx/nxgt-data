`defineImageSet(options)` returns an image set whose `process(input, { crop })` turns an upload (bytes, a buffer, a `Blob` or a stream) into square WebP variants. `sizes` (default `[256, 64]`), `maxBytes` (5 MiB), `maxPixels` (50 million), `minSide` (the largest size) and `quality` (80) and `concurrency` (2: how many uploads decode at once, which bounds memory) are checked when the set is defined, a bad one throwing a `TypeError` that names it. An upload is refused before anything is stored: too many bytes or pixels (`TOO_LARGE`), a format that is not a JPEG, PNG, WebP or HEIC, judged by its first bytes, or a HEIC this machine cannot decode (`UNSUPPORTED_TYPE`), damaged content (`UNDECODABLE`), a short side under `minSide` (`TOO_SMALL`). The crop is the centred square unless `crop: { x, y, size }` gives one, in the picture as a person sees it after EXIF rotation; a crop that is not whole numbers or does not fit the image is a `RangeError`. The result is `{ source, variants }`, one `image/webp` square per size in the order of `sizes`, with the ICC profile, EXIF (GPS included) and every other metadata removed.
