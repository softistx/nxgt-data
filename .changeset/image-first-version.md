"@nxgt/image": minor
---

First version of `@nxgt/image`, for avatar and photo uploads on Bun's own `Bun.Image`, with no required dependency (`@nxgt/s3` is an optional peer, for `@nxgt/image/s3`). It needs Bun 1.4.1 or later: `defineImageSet` throws a `TypeError` on an older Bun, where `Bun.Image` does not exist.

`defineImageSet(options)` returns an image set, which exposes its `sizes`, whose `process(input, { crop })` turns an upload (bytes, a buffer, a `Blob` or a stream) into square WebP variants. `sizes` (default `[256, 64]`), `maxBytes` (5 MiB), `maxPixels` (50 million), `minSide` (the largest size), `quality` (80) and `concurrency` (2: how many uploads decode at once, which bounds memory; the queue behind it is unbounded) are checked when the set is defined, a bad one throwing a `TypeError` that names it. A call holds about 4.5 bytes per pixel (150 MB for a 36 MP photo), the crop being read as the PNG streams. A `Blob` of unknown size (Bun's `S3File`) is read through the byte cap.

An upload is refused before anything is stored, with an `ImageError` whose `code` is `TOO_LARGE`, `UNSUPPORTED_TYPE`, `UNDECODABLE` or `TOO_SMALL` and whose `reason` (`bytes`, `pixels`, `format`, `heic-unavailable`, `decode` or `dimensions`) tells which limit or check refused it: too many bytes or pixels, a format that is not a JPEG, PNG, WebP or HEIC (judged by its first bytes), a HEIC or another format this machine cannot decode, damaged content, a short side under `minSide`. The crop is the centred square unless `crop: { x, y, size }` gives one, in the picture as a person sees it; orientation applies to a JPEG only. A crop that is not whole numbers or does not fit the image is a `RangeError`. The result is `{ source, variants }`, one `image/webp` square per size in the order of `sizes`, with the ICC profile, EXIF (GPS included) and every other metadata removed.

The subpath `@nxgt/image/s3`: `bindImageStore(set, bucket)` stores the variants in a `@nxgt/s3` bucket whose key takes a `size` beside its other params. `replace(params, input, { crop })` processes the upload, puts every size as `image/webp` and returns `{ version, variants }`, `version` being 16 hex characters of the SHA-256 over the variants' bytes. `remove(params)` deletes every size (a missing object is fine); `presignGet`, `bytes` and `keyFor` take a size, and a size outside the set is a `RangeError` that names the call (`presignGet: size 128 is not one of the set's sizes (256, 64)`). Objects are never public: no `acl` is passed, so bind the bucket without a public default one. A refused upload writes nothing; a failed put deletes only the keys whose put succeeded, never the refused one, and rethrows the first error. Use a fresh id per upload (`crypto.randomUUID()`): replace under the new id, store it, then remove the former id's set.
