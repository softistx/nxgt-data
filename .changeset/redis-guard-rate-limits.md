'@nxgt/redis-guard': minor

First release of `@nxgt/redis-guard`, guards on Bun's own `RedisClient`, starting with rate limits. `defineRateLimit({ name, key, limit, per, burst })` describes a limit and `bindRateLimit(client, definition)` binds it, with `consume`, `enforce`, `peek` and `reset`, and an optional `cost` per call. Each check is GCRA as one Lua script over one key, holding the server's time at the last write and the bucket's offset beyond it, sent by its SHA-1 and falling back to `EVAL` on `NOSCRIPT`. The script is timed by the Redis server's `TIME`, never the host's clock, and a server clock that goes back never refills a bucket. A stored value the script could not have written reads as a full bucket. A denial and a `peek` write nothing, and the key expires when its bucket is full again. The script counts in exact integers, in units of 1/limit µs, so a burst taken one request at a time allows exactly the burst at any rate; a `burst × per` above what that can hold exactly (9,007,199,254,740) is refused at definition. Every result is a delay in milliseconds (`resetAfter`, `retryAfter`), never a date. Its error is `GuardError`, with `RATE_LIMITED` (carrying `retryAfter`) and `COST`, naming the definition and never the key or the params.
